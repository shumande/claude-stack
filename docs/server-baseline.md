# Базовая защита и обслуживание сервера — готовое решение

> Написано 22.08.2026 по итогам разбора двух живых VPS (IONOS и Hostinger).
> Цель: не вспоминать каждый раз «а что мы там настраивали», а раскатать
> одинаковую защиту на любую новую машину за пять минут и получать отчёт
> о её состоянии раз в месяц.

## Что даёт

| Скрипт | Что делает | Когда запускать |
|---|---|---|
| [`scripts/server-baseline.sh`](../scripts/server-baseline.sh) | SSH только по ключу · fail2ban · ufw · автообновления безопасности · аудит открытых портов | **один раз** на новой машине, идемпотентен |
| [`scripts/server-maintenance-check.sh`](../scripts/server-maintenance-check.sh) | отчёт в Telegram: обновления, нужна ли перезагрузка, версия n8n, срок сертификата **по факту отдачи**, баны, состояние SSH/файрвола, открытые порты, диск | **раз в месяц** по systemd-таймеру |

Принцип: **проверка докладывает, человек решает.** Автообновление прода без
глаз — способ однажды проснуться со сломанными воркфлоу.

## Установка на новую машину

```bash
# 0. СНАЧАЛА ключ, иначе потеряешь доступ (скрипт это проверяет и откажется работать)
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@HOST

# 1. базовая защита
scp scripts/server-baseline.sh root@HOST:/root/
ssh root@HOST 'bash /root/server-baseline.sh'

# 2. ежемесячная проверка
scp scripts/server-maintenance-check.sh root@HOST:/root/monthly-maintenance.sh
ssh root@HOST 'chmod +x /root/monthly-maintenance.sh'
```

`/root/.maintenance.env` (права 600):

```
TELEGRAM_BOT_TOKEN=...
CHAT_ID=...
HOST_LABEL="Понятное имя машины"
CERT_HOSTS="домен1 домен2"      # проверяются по факту отдачи на 443
N8N_CONTAINER="root-n8n-1"      # необязательно
N8N_URL="https://n8n.example"   # необязательно
COMPOSE_FILE="/root/docker-compose.yml"
```

Таймер:

```bash
ssh root@HOST 'cat > /etc/systemd/system/monthly-maintenance.service <<U
[Unit]
Description=Ежемесячная проверка обслуживания
[Service]
Type=oneshot
ExecStart=/root/monthly-maintenance.sh
U
cat > /etc/systemd/system/monthly-maintenance.timer <<U
[Unit]
Description=Первое число месяца, 09:00
[Timer]
OnCalendar=*-*-01 09:00:00
Persistent=true
[Install]
WantedBy=timers.target
U
systemctl daemon-reload && systemctl enable --now monthly-maintenance.timer'
```

## Шесть граблей, на которых мы уже стояли (22.08.2026)

Каждая найдена на живой машине, не выдумана.

1. **`99-hardening.conf` не работает.** sshd берёт **первое** вхождение параметра,
   а cloud-init кладёт `50-cloud-init.conf` с `PasswordAuthentication yes`.
   Файл обязан называться **`00-`**. Симптом: правило написал, `sshd -T` показывает `yes`.
   → *всегда проверять `sshd -T`, а не факт записи файла.*

2. **ufw не закрывает порты Docker.** Docker пишет правила в nat-таблицу мимо ufw.
   `ufw deny 3000` создаёт иллюзию защиты. Единственный рабочий способ —
   публиковать порт как `127.0.0.1:PORT:PORT` в compose.
   → *после настройки файрвола проверять порты снаружи, с другой машины.*

3. **Просроченный сертификат прячется за Cloudflare.** Traefik 8 дней подряд не мог
   продлить сертификат (`Cannot negotiate ALPN protocol "acme-tls/1"` — TLS-ALPN-01
   не проходит через прокси Cloudflare). Сертификат истёк **57 дней назад**, и никто
   не заметил: снаружи Cloudflare отдаёт свой живой, режим Full принимает любой origin.
   Переключение в Full (strict) уронило бы сайт мгновенно.
   → *проверять срок сертификата, который РЕАЛЬНО ОТДАЁТСЯ на 443, а не файлы
   в `/etc/letsencrypt/` — traefik хранит их в `acme.json`.*
   → *за Cloudflare использовать DNS-01 или Origin Certificate, не TLS-ALPN-01.*

4. **Экспорт молча отдаёт пустой файл.** Не про сервер, но про тот же класс ошибок:
   выгрузка из Lightspeed за год возвращала CSV с одной шапкой и нулём строк,
   без ошибки. → *автоматика проверяет содержимое результата, а не факт успеха команды.*

5. **`systemctl is-active` + `grep active` = ложное срабатывание.** Для отсутствующего
   сервиса возвращается `inactive`, и grep радостно совпадает.
   → *сравнивать строку целиком: `[ "$(systemctl is-active X)" = "active" ]`.*

6. **`ssh.service disabled` — не поломка.** На Ubuntu 24.04 SSH поднимается через
   `ssh.socket`, порт 22 держит сам systemd. Перед перезагрузкой проверять надо
   **`ssh.socket`**, иначе испугаешься на ровном месте.

## Порядок работ на живой машине с чужим продом

1. **Бэкап до единого изменения**: конфиги, экспорт данных приложения, tar тома,
   digest текущего образа для отката. Копию **увести с этой машины** — бэкап,
   лежащий на сервере, который ты сейчас перезагрузишь, это не бэкап.
2. SSH → fail2ban → файрвол (в этом порядке; порт 22 разрешить ДО включения ufw).
3. Обновление приложения: **версию закреплять явно** в compose. Плавающий `:latest`
   плюс watchtower = молчаливые обновления прода.
4. Перезагрузка — в последнюю очередь, после проверки автозапуска всех служб.
5. После каждого шага — **проверка снаружи**, а не по своему же выводу.
