# diarize-call — разбор звонка по голосам, локально

Проверено 15.09.2026 на реальном 50-минутном двухголосом звонке (`Alexandr.m4a`) — работает.
Не переделывать заново без причины, только докручивать.

## Зачем

Spokenly (macOS-приложение, стоит локально) умеет распознавать речь бесплатно и быстро,
но разделение говорящих (diarization) у него — только в Pro-подписке. Вместо покупки:
берём открытую модель `pyannote/speaker-diarization-community-1` (GitHub `pyannote/pyannote-audio`)
для вопроса «кто когда говорит», и уже готовый локальный Spokenly — для вопроса «что сказано».
Всё бесплатно, всё своё, ничего никуда не уходит.

## Что нужно один раз

1. `pip install pyannote.audio` (torch уже должен быть — обычно стоит из других AI-проектов).
2. Аккаунт на huggingface.co → принять условия модели
   [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)
   («Agree and access repository»).
3. Токен: [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) (read-доступа хватит).
   Не коммитить, не класть в файлы — только `HF_TOKEN=...` в окружении на момент запуска.
4. Spokenly должен быть запущен (обычный фоновый процесс приложения).

## Пайплайн (3 шага)

```bash
# 1. Диаризация — кто когда говорит (даёт .segments.json рядом с исходником)
HF_TOKEN=hf_xxx python3 diarize.py /path/to/call.m4a

# 2. Нарезать аудио по отрезкам
python3 extract_clips.py /path/to/call.segments.json /tmp/call_clips

# 3. Распознать каждый отрезок отдельно (напрямую через локальный порт Spokenly,
#    минуя ручные вызовы MCP-инструмента по одному — иначе на длинном звонке
#    получаются сотни отдельных вызовов)
python3 transcribe_all_segments.py /tmp/call_clips/manifest_abs.json /tmp/call_transcribed.json
```

Дальше — маленький скрипт на 10 строк склеивает соседние реплики одного спикера и
подписывает имена (см. пример сборки в истории коммита/сессии от 15.09.2026, ai-firma).

## Важные грабли (уже пойманы, не наступать снова)

- **torchcodec на macOS сломан** («Could not load this library: .../libtorchcodec_image.dylib»).
  `diarize.py` уже обходит это — грузит аудио через `soundfile` в память и передаёт pyannote
  словарём `{"waveform": tensor, "sample_rate": int}`, а не путём к файлу. Если ошибка вернулась —
  чинить тем же способом, не гнаться за починкой torchcodec напрямую.
- **Склейка нескольких отрезков в один файл с паузами между ними НЕ работает** — Spokenly не
  режет по вставленной тишине, отдаёт весь файл одним куском текста без внутренних таймкодов.
  Проверено, не тратить время на эту идею снова. Только по одному отрезку на файл.
- **Spokenly слушает `localhost:51089`** и принимает обычный JSON-RPC (MCP-протокол) через
  `curl -X POST`. `mcp-bridge.sh` в `~/Library/Application Support/Spokenly/` — просто прокладка
  между stdin и этим портом. Так и вызывается напрямую в `transcribe_all_segments.py`.
- **Относительные пути до клипов не находятся** — Spokenly-приложение резолвит их не от cwd
  скрипта. Всегда абсолютные пути (`extract_clips.py` уже это учитывает).
- Метки `SPEAKER_00`/`SPEAKER_01` от pyannote не именованы — сопоставлять с реальными людьми
  нужно по опорным фразам в тексте (упомянутое имя, характерная фраза), не наугад. Самые первые
  1-2 реплики короткого приветствия в начале звонка — зона риска (модели не хватает аудио на
  разогрev), доверять чуть меньше, чем середине разговора.
